# 图表、论文修订与最终交付

适用：结果已存在，需要变成可信、清楚、可复现的表达。没有论文交付时，按需保留图表、报告和工程打包部分。

## 1. 先把证据组织成图表任务

每张图/表先回答一个问题，再选形式。主文优先放支撑核心主张、机制和必要对照的材料；补充材料承载完整性、复现和扩展分析，但不能藏掉会改变主结论的反例。

建立图表约定，按需包含：

| 项目 | 要明确的内容 |
|---|---|
| 论证职责 | 回答的问题、支持的主张 |
| 数据来源 | 运行/版本、输入文件、字段、范围 |
| 选择规则 | 场景/样例如何选，是否事后选例 |
| 统计口径 | 分母、独立单位、误差表示、配对关系 |
| 处理 | 对齐、滤波、插值、派生公式、排除规则 |
| 视觉形式 | 曲线/散点/分布/表格/机制图与必要面板 |
| 版面 | 最终单/双栏或演示尺寸、字号和导出格式 |
| 图注 | 条件、比较对象、处理说明、阅读结论 |
| 验收 | 数据可追溯，最终尺寸可读，图文数字一致 |

一个图不承担新信息时，合并或移除。过程表若比多条状态曲线更能解释完整事件链，可以用表；不要为了“高级感”增加图形层。

## 2. 用脚本生成可追溯科学图

沿用项目绘图后端与用户明确偏好。没有约定时，选择适合科学数据的标准绘图工具，保存生成脚本和必要派生数据，不把每次风格修改变成手工改图。

数据图使用真实数据生成。AI 图像可用于概念插画/背景素材，不替代定量曲线、实验截图或实测证据。编辑示意图也要准确表达方向、变量和组件关系。

统一同一比较中的坐标、单位、颜色含义、线型和尺度；必要差异明确标出。原生按目标尺寸设计，不把宽图简单缩小到文字不可读。

交付格式按用途选择：论文常需矢量 PDF、可编辑 SVG 和预览 PNG；不强制所有任务都输出三种。保存用户使用图对应的准确脚本与数据版本。

## 3. 显示处理与实验判断分开

滤波、平滑、插值、裁边和选例均要有用途及来源记录。

- 显示滤波不自动改变实验标签、告警判定和统计结果。
- 非因果双向滤波可以用于明确的离线展示，不能冒充在线算法可得信号。
- 多信号对齐使用共同有效区间；外推、缺失填补和重采样若必要，明确方法与影响。
- 不剪掉真实峰值、失败或低表现片段来改善视觉印象。
- 示例选择可以服务解释，但要保留全样本结果与选择依据。
- 实测点云不自动等于辨识出的极限曲面，视觉包络不自动变成物理结论。

图形布局可以优化，事实不能“美化”。重要处理若可能改变结论，做针对性敏感性检查；无需对纯裁白边等低风险编辑重复整个实验。

## 4. 先查最终尺寸，再查最终页面

检查至少包括当前改动涉及的项目：

- 图例、轴标签、单位、刻度、色条、面板字母是否完整且可读。
- 多面板对齐、空白、线条遮挡、双轴对应和重复标签。
- 字体嵌入、输出边界、矢量/位图分辨率和裁边安全区。
- 图注是否脱离正文仍能理解；图中数据是否与表格、正文一致。
- 在文稿实际栏宽/页面中看一遍，而非只看大尺寸预览。

能渲染就实际查看图和改动页。文本提取、成功编译或脚本无报错都不能代替视觉检查。当前环境不能查看时如实标记未完成的视觉验证。

## 5. 用证据组织论文

从已有证据写一句核心价值：在何种条件下，为谁解决什么问题，最有分量的结果是什么。用它选择内容，不强制固定句数、贡献数量或章节模板。

| 部分 | 主要任务 |
|---|---|
| 摘要 | 问题、关键机制、主要结果与适用条件 |
| 引言 | 重要需求、真正缺口、解法与贡献 |
| 相关工作 | 最近方法、差异及为何需要当前机制 |
| 问题定义 | 对象、输入输出、目标、可用信息与约束 |
| 方法 | 解释各设计如何解决问题，给可实现的机制 |
| 实验 | 设置→观察→解释，按论证职责组织 |
| 讨论/结论 | 已证明价值、实际边界、直接相关后续方向 |

研发时间线留在研究记录，论文不按 milestone 日志堆叠。不把文件名、审计流水和内部调试细节当贡献；保留真正影响复现和解释的条件。

## 6. 清楚有力，但不改写事实

- 让最强证据承担主线，解释结果对应用/研究意味着什么。
- 保留数字、单位、样本量、阈值不等号、因果方向和统计口径。
- 不机械禁用 only、limited、however 等词，按语义判断。
- 删空泛引导、反复辩解和无依据自贬；必要边界在相关主张处准确交代，不反复铺免责声明。
- 负结果写清条件、幅度与影响，不泛化成整体失败，也不包装成优势。
- 不为好看换指标、筛有利样本、删关键反例或隐去学习成本。
- 尚未验证的机理标为解释/假设，不能在润色中升级为已证实因果。
- 保留已经自然、准确的作者表达，避免为了“AI 风格统一”重写整篇。

本项目提炼出的反防御原则是“突出证据支持的价值”；它不包含“不说输”或隐藏不利证据的授权。

## 7. 修订已有稿件

先明确权威源码、参考 PDF、范围、修订强度与比较基线。用户给同版 ZIP+PDF 时，ZIP 用于编辑，PDF 用于阅读/版面参考；不要混入工作区旧同名文件。

修改前保存适当 checkpoint，沿用既有版本管理。区分相对最初稿的累计差异与相对上一轮的本轮差异。仅改本轮范围；若用户未要求逐章停止，就完成已请求范围。

事实核对要指向具体对象：阈值、输入、训练/固定方式、建议/实际动作、统计分母、延迟的计时范围。使用“作者确认”“本地材料核验”“待核实”等状态，不能凭缺材料重写实验类型。

需要增删稿时，调用可用的专项修订流程，或生成等价的净稿与完整增删对照。沿用用户标记样式；只高亮新稿不能冒充同时含删除内容的对照。

验证修改范围、事实保真、公式/标签/引用、图源及标记完整性。长段移动或重写特别检查旧文与新文均未丢失。报告前后摘录必须来自真实对应版本。

## 8. 工程和文稿的最终交付门

交付粒度匹配任务：工程可交代码、配置、运行入口、结果及必要依赖；论文可交净稿、可编辑源、图表和需要的增删稿；不打包无关缓存、大日志或凭据。

1. **固定最终对象。** 确认用户实际将打开的路径/文件名和版本。
2. **同步最终产物。** 临时工作目录完成后，更新正式交付位置。
3. **核对包内容。** 用必要依赖清单或既有打包脚本，不递归压入整个工作区。
4. **隔离检查。** 对需独立使用的包，解压到独立目录运行相应构建/最小复现；识别硬编码绝对路径、缺字体/图片/数据和环境依赖。
5. **核对用户视图。** 查看最终 PDF/图/应用效果；确认最终包生成的内容与审阅版对应。
6. **更新入口。** 记录命令、版本、验证结果和明确缺口，再报告完成。

源码可独立编译不等于原始实验可独立复现。若大体积数据未随包提供，说明完整复现所需的数据入口和权限；不能把“编译通过”写成“全部实验复现通过”。

环境不能完成某项验证时交付现有可用成果并指出具体未核验项，不把未检查冒充通过。不因历史无关警告擅自扩大修改范围。

## 9. 最后的回复

先给产物链接，再用少量文字说明变化、实际检查和剩余事项。用户只要文件时保持简洁。不要用长篇自评代替结果，也不要让用户从多份同名文件中猜哪一份是最终版。
