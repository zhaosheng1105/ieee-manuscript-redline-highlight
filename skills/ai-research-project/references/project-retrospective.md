# 案例复盘：一个 AI 协作科研工程项目如何从构想到论文

本案例依据 `thermal_tire_ggv` 工作区中现存的研究记录、实验报告入口、图表约定和修订报告重建，不是完整聊天历史，也不能确定每次决策最初由谁提出。
下文将“记录明确发生的事情”与“可迁移的工作规则”分开。具体数据只用于说明流程为什么升级，不作为未来项目的默认目标。
这是一条科研工程路线：研究定位、可运行系统、逐级验证、证据整理、图表和论文共同推进；软件产品等项目可保留阶段门与交付机制，替换科学验证部分。

重点学习 milestone 怎样设计、怎样逐步验证、怎样由结果改变下一阶段时，读[PCASE01 详细设计案例](milestone-case-thermal-tire-ggv.md)及[通用设计手册](milestone-design-and-validation.md)。本页保留包含图表、写作和交付在内的全程概览。

## 1. 先辨认当前事实，再回顾历史

- 项目曾多次调整方法主线、模型和论文版本，文件日期、目录名称或“主记录”称谓不能单独决定权威性。
- 2026-11-07 修订明确以作者提供的最新 ZIP/PDF 为底稿；旧 `paper_writing/sections/` 与该底稿不同，不应直接覆盖。[E01]
- 实车实验的当前定位为作者确认的**在线开环测试**：车载智能体接收实时测量、生成建议、更新记忆，MPC 继续使用工程师设置。[E01]
- 早期记录曾把本地离线分析脚本的工作方式推断成整项实车实验的部署方式；最新修订已撤销该推断。离线复核工具与在线实验可以同时存在。[E01]
- 当前部署事实依据作者确认；本轮修订并未独立检查新增在线进程日志。数值复核、部署确认和新日志核验应分别写明来源。[E01]
- 因此，本案例中的早期记录用于解释当时如何推进，不把其每个科学表述当作当前论文事实。

迁移规则：维护“当前事实、来源、确认方式、替代了哪条旧判断”。发现冲突先核对材料用途与最新明确纠正，不机械地让代码文件名、旧 README 或修改时间压过作者说明。

## 2. 实际推进过程

### 工程起步：从成熟平台抽出最小研究环境

在研究主线收敛前，项目先从已有赛车栈抽出独立的最小环境，复用规划器和控制器，保留必要节点与资产来源。[E14]
因此，这里的“从 0 到 1”是从研究需求到完整成果，不意味着从零重写所有基础软件。
启动检查逐步从进程/消息存在推进到实际速度、位移和控制反馈，区分离线链路通过与车辆真正运动。
早期“车辆出生在维修区”的判断后来被坐标证据推翻：仿真 NED 与规划 ENU 的轴及原点不同，基于旧判断的初始化修改被撤回。
修订保留真实 CAN 连通和位移证据，但撤回“路线跟踪已正确”的过强解释；当时未重测的闭环明确留待验证，没有扩大对齐阈值制造通过。
产物包括最小工程、来源记录、启动入口、诊断脚本、故障记录和分层验收。
可迁移规则：先保护并复用可信底座，检查单位、坐标、时间和实际生效链；错误假说应同时修正代码、记录与后续验收。

### 阶段 A：将模糊想法变成研究问题

起点是车辆在不同弯道和热条件下如何使用能力，以及能否通过交互逐步学会何时继续提高需求、何时停止。
早期文档先写一句话定义和核心矛盾，再把世界模型、决策、执行、反馈和长期记忆拆成不同职责。[E02]
它还定义了物理边界、运行边界、认知、调节动作等概念，避免把“提高参数”解释为“提高物理能力”。
产物是研究故事线、术语表、三个研究问题，以及每个问题需要的证据，而不是一开始就确定最终网络和论文结论。
升级理由是“会学习的系统”必须有可检验行为：新增反馈应持续改变下一次选择，不能只有一个带新名称的增减规则。
可迁移规则：先明确对象、矛盾、机制和观察量，再决定实现；先写待检验效果，不预填成功结论。

### 阶段 B：用文献和源码共同约束方案

文献核查把最接近工作映射到具体主张，识别已有的逐圈学习、信息增益、热条件模型和滑移检测。[E03]
源码审查同时发现底层将前方多个倍率压缩成一个标量，原平台还不能实现设想中的逐点独立配置。[E02]
产物包括主张—来源表、元数据修正记录、当前接口能力清单，以及需要新增的研究模块。
升级理由是研究名称不能代替增量，架构图也不能代替已经可用的执行接口。
可迁移规则：相关工作回答“别人已经做到了什么”，代码核验回答“我们现在实际能做什么”；两者共同确定最小可实现贡献。

### 阶段 C：复用已有数据，先建立完整预测管线

M0 利用已有 47 个固定倍率完整圈建立动作响应基础；没有因数据不是最终策略生成就全部重采。[E04]
M1 补充切换、验证和测试数据，完成采集、训练、独立预测与在线只读候选推演。
关键发现是预测误差较小仍不等于能选对动作：候选排序没有通过，记录明确保留这一结果。[E04]
产物是可运行数据管线、模型、独立评价、失败诊断和下一阶段需要补齐的信息。
升级理由来自任务机制：短时状态误差不能充分表示较长区域中不同能力设置的后果。
可迁移规则：先把最小数据闭环做通，同时检查预测是否改变正确决策；代理指标好不能替代任务验证。

### 阶段 D：缩小范围，验证一次真正的反馈学习

M2 先选择少数区域和条件建立响应记录，再做独立复测，检查旧经验遇到新反馈时是否修正。[E05]
有代表性的过程包括原先通过的设置在新试验预警，随后回退、细化、保持，并在新会话再次验证。
方法转向较简单的区域响应先验与显式记忆；原 GRU 保留为独立预测组件，没有把模型身份混在一起。
产物是局部试次、事件链、修正前后经验、后续真实执行和结构化审计。
升级理由是先证明“反馈改变未来行为”成立，再扩大覆盖范围，比先堆完整系统更容易定位问题。
可迁移规则：围绕一条完整机制链做小规模验证：输入/动作→实际生效→响应→内部状态变化→下一次行为。

### 阶段 E：扩展接口，再完成整系统闭环

M3 将原标量接口扩展为多个规划阶段独立读取连续空间曲线；核对恒定输入等价、远端变化响应、读回一致性和时延。[E05]
M4 才把局部机制扩展到全圈，由智能体选择试探、获得真实响应、修改经验，并在新进程加载后继续运行。[E06]
正向经验要求动作充分生效、数据有效、需求充足；低需求平稳通过和无效观测有不同记录状态。
产物是可执行接口、冻结主方法、完整会话、记忆和重启复用证据。
升级理由是“发布过动作”不代表优化器真正使用，“保存了文件”不代表新进程真正复用了经验。
可迁移规则：系统验证必须穿过真实边界；分别证明传输、采用、效果和持久化，不能只检查函数返回成功。

### 阶段 F：公平比较揭示收益与代价

M5 对多种策略使用共同正式预算，计入预警、恢复和重新对齐，并记录基线开发调参及初始知识差异。[E07]
结果没有支持普遍模型优势：静态基线在该冷启动预算内领先，模型与规则的差异依条件变化。
一次监督器故障被保留，修复异常路由后独立冻结、补录，并报告将原故障纳回的保守敏感性。
产物是预声明协议、逐次结果、统计单位、完整成本、故障修订说明和敏感性分析。
升级理由是系统“能够学习”与“值得花成本学习”是两个问题；后者需要包含获取知识的全部代价。
可迁移规则：保留强基线与失败；先定位目标、决策和运行成本，不因为比较不理想就默认需要更大模型。

### 阶段 G：依据结果探索新分支，但保留主线身份

M5b 单独研究提供人工先验后的局部适应，验证小幅增量、连续确认、停止试探后的保持及重启复用。[E08]
该分支保留人工先验来源，不把整张初始地图算成自主发现，也不覆盖原冷启动实验。
后续记录将主线重新聚焦到自主边界探索与动作条件推演；人工初始化转为补充分析。[E09]
产物包括独立目录、独立冻结版本、来源标签，以及更新后的贡献—证据映射。
升级理由是新方向可以补充已有结果，但不能为了容易讲出好结果而悄然替换用户真正的研究问题。
可迁移规则：保存有效探索分支；主次由当前目标与证据共同决定，重排叙事时不改写历史结果。

### 阶段 H：迁移和实车分别建立适用范围证据

Imola 迁移工作案例使用冻结源模型和空目标记忆，记录目标访问、支持扩张、回退复验以及跨进程复用。[E10]
报告区分这次运行的描述性前后比较与更广泛的多赛道独立重复，没有把工作案例替代全部泛化验证。
实车材料用于核查逐圈经验、事前输出、实际工程师设置、告警和后续处理；最新部署口径遵循作者确认的在线开环测试。[E01]
产物是目标域报告、尝试表、协议调整、数值复核和清楚的执行角色说明。
升级理由是模型冻结、记忆清空、真实执行和人工控制角色，会直接改变“迁移”及“实车验证”能支持的结论。
可迁移规则：跨域验证要写清共享与重置对象；分别说明建议生成、实际控制和分析复核，避免混成一种执行方式。

### 阶段 I：将实验记录转换成图表证据包

项目先为每图确定论证问题、源数据、字段、选择规则、版本和图注，再导出图表包，随后统一正文。[E11]
项目图表约定采用紧凑单栏与共享轴，其中四节点图的紧凑单栏布局是用户明确要求；图形按最终尺寸重新布局，而不是把宽版直接缩小。[E12]
显示滤波、时间对齐、插值等有独立记录；原始数据与实验判定保留，显示优化不被用于重新制造结果。
产物包括可编辑图、源数据快照、脚本、来源清单、图注和视觉检查记录。
升级理由是漂亮图不能自动成为证据；每张图必须回答具体问题，也必须在最终论文尺寸下可读。
可迁移规则：先证据职责后形式；科学数据用可复现绘图工具生成，选择和处理规则随图保存。

### 阶段 J：论文收敛、分章修订和独立交付

论文按问题与贡献组织，不按研发里程碑顺序复述；研发史、逐次记录和详细审计保留在支撑材料中。[E09]
后续修订先确认权威底稿与章节范围，保留检查点，按作者纠正处理部署事实，不擅自扩大修改范围。[E01]
图文集成后编译、逐页渲染，检查引用、字号、浮动、越界与字体；源包在独立目录重新构建。[E13]
产物是净稿、标记版、可编辑源包、修订报告、验证记录和最短复现入口。
升级理由是本机能编译不等于交付包可用，语言流畅也不能弥补事实来源或底稿判断错误。
可迁移规则：最终交付同时通过内容、构建和视觉验收；研究事实与写作呈现分别管理。

## 3. 十个高价值经验

1. **一个当前状态入口。** 每阶段更新问题、方法版本、证据、结论和下一不确定性；另存历史，不让旧计划伪装成现状。
2. **一个阶段只优先回答一个关键问题。** 验收由问题决定，阶段完成与最终贡献成立分别判断。
3. **利用现有资产起步。** 数据、控制栈和工程基线先核查再复用，缺哪类证据就补哪类。
4. **验证作用链。** 准确预测、正确选动作、实际生效、任务改善、跨进程复用分别需要证据。
5. **简单模型可以承载系统创新。** 先证明模块职责和交互机制，不用结构复杂度代替贡献。
6. **事前协议与事后记录配套。** 冻结指标和预算，也保留真实故障、修订和未达到目标的运行。
7. **版本和来源不能混。** 不同模型、初始化、会话和部署方式保持身份；正式测试参与开发后不继续冒充独立测试。
8. **用户纠正进入长期记忆。** 更新当前事实与受影响产物，标明撤销的旧推断，不让下个会话再次犯同样错误。
9. **正文讲贡献，记录保留过程。** 不利结果如实保留，细节按论证职责进入正文、补充或复现材料。
10. **交付可以脱离当前环境使用。** 源码、输入、依赖、命令和验证结果形成闭环，不只交付一张图或一份 PDF。

## 4. 不可照搬的项目参数与选择

- 赛道、车辆、温度档位、摩擦映射、空间单元数量和尺度属于本项目条件。
- GRU、ExtraTrees、树数、叶节点大小、预测时域、输入字段和学习规则都要按新问题重选。
- 47 圈、600 s、3 次重复、0.02 增量及各门槛不是通用的充分样本量、预算或安全保证。
- 在线开环、闭环、离线复核、人工先验等是执行事实，不能因为复用模板而预先套用。
- IEEE 单栏尺寸、图数量、章节安排和已卸载绘图工具是此项目的出版与用户偏好，不是所有学科的默认规范。
- 原绝对目录、环境名、运行命令、硬件接口和物理恢复动作不可复制到新项目后直接执行。
- 可以复用的是问题拆解、验收门、版本管理、证据链、用户偏好继承和交付方式。
