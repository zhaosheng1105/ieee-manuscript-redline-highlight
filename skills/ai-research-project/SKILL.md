# 个人 AI 科研工程：从零到交付

让用户主要提供方向、关键判断和必要资源，由 AI 持续承担资料梳理、方案落地、代码与实验、证据整理和交付验证。每一阶段都交付能检查、能复用、能继续推进的结果，减少用户重复解释背景、口径和工作习惯。

这是一套从 `thermal_tire_ggv` 起步、随用户后续项目持续更新的个人工作法。适用于算法、仿真、数据分析、实验系统和论文一体化项目；无论文或无物理实验时跳过对应分支。阶段设计与逐步验证、最终选定的实验都是重点参考，分别回答“研究怎样推进”和“最终怎样组织证据”。不要默认新项目也使用车辆、ROS、GGV、IEEE 或某种模型。

接手项目时先读[个人偏好与案例索引](references/personal-profile.md)。把用户明确要求、案例提炼的可覆盖习惯和项目专属配置分开继承；新的明确指示优先。

## 第一次接手或恢复工作

1. **读取当前任务与现状。** 检查项目指令、目录、README、进度记录、最新交接、必要代码及产物。先排除 build、缓存、大日志和历史备份，需要证据时再定点读取。IDE 打开的文件只是线索，不自动成为权威版本。
2. **确定本轮范围。** 识别用户要的是全程推进、当前里程碑、诊断、实验、图表还是写作。继承已明确的授权、约束与偏好，不重复询问已知信息，也不把全流程 skill 当作扩大本轮任务的授权。
3. **找出当前最关键的不确定性。** 用最小可验证动作推进它；缺信息先查项目资料和可用连接。只有会实质改变方向、正确性、成本或操作边界的未知项才询问，同时继续不依赖答案的工作。
4. **建立或接续项目记忆。** 优先更新现有主记录；缺少时用[项目记忆模板](assets/project-memory-template.md)建立适量记录。不要为一次小修复额外铺设文档体系。
5. **加载本阶段手册并开始执行。** 简短说明目标、当前阶段和马上要完成的可检查结果；不要停在计划或能力介绍上。

| 实验设计、补实验、组织实验结果/章节 | [实验与证据](references/experiments-and-evidence.md)及[个人实验索引](references/personal-profile.md)，再读其中相关精选案例 | 以用户已选结构为参考的实验方案、证据及图文 |

| 用户只给一句话，希望沿用协作习惯 | [常见请求的执行方式](references/request-recipes.md) | 进入恰当阶段，不机械跑全流程 |
| 理解方法来源、复盘类似问题 | [原项目过程与经验](references/project-retrospective.md) | 阶段实例、纠错经验、不可照搬的配置 |
| 将新项目、milestone设计、最终实验或新偏好沉淀到 skill | [个人技能更新](references/skill-evolution.md) | 合并后的个人规则、阶段/实验案例及同步分发包 |

仅读取相关手册，不要求每次遍历全部文件。发现证据不足，补最有价值的实验；发现接口不成立，修最小系统；发现主张过宽，收窄主张。不能靠修改图文掩盖上游问题。

## 默认协作约定

这些是本 skill 的可覆盖默认值，用户当前指示与项目明确约束优先。

- **直接完成已授权工作。** 方案后接实现，实现后接验证，验证后更新最终产物。除非用户要求逐步停下，不在每个小步骤重复求确认。
- **先继承，再改进。** 保留可用底座、已确认术语和有效表达。复杂度只在能解决具体问题时增加，不为展示工作量重构项目。
- **中文沟通，语言随交付目标。** 技术符号和代码标识符保持一致；英文论文按目标学术文体写，不把聊天口吻写入正文。
- **及时、具体地同步。** 更新说清新发现、影响和下一项工作。最后先给可点击产物，再说明关键变化、验证和确切缺口。
- **事实先于叙事。** 分开实际运行、作者确认、代码可见实现、分析推断和待实施设想。不能因“本地没有日志”否定作者确认，也不能把作者确认升级为数值已本地复核。
- **贡献要鲜明，证据要完整。** 组织最有价值的能力与机制，保留决定结论的负结果、失败和评价条件。去掉反复辩解，不隐藏不利证据。
- **数据—代码—结果—图文一致。** 重要数字指向来源、处理方法、统计单位和版本。方案写了、接口发布了、文件生成了，都不等于行为已验证。
- **随阶段留下续接入口。** 写清已完成、未完成、下一项具体动作与验收，不让下一轮 AI 靠猜测重建项目。

## Milestone 的设计与接续

以“这一阶段消除哪个关键不确定性”拆解路线，并明确已有前提、最小验证、实际生效证据和结果对应的下一决策。先粗排能力依赖，重点细化最近可执行阶段；已有证据充分的环节直接复用，用户只做局部任务时保持原范围。

[本项目设计案例 PCASE01](references/milestone-case-thermal-tire-ggv.md)保留 M0 数据起点、M1 预测与排序、M2 局部反馈、M3 空间执行接口、M4 整圈闭环、M5 同预算比较、M5b 先验辅助分支，以及后续迁移/实车的设计转折。重点借鉴验证问题之间的依赖，不照搬编号和配置。

“实现已完成”“检验已完成”“假设获得支持”分别记录。负结果可以完成本阶段研究，却不能放行依赖该假设成立的后续路径；下一阶段按证据修复、补验或改变方案。阶段结束写回新认识与下一不确定性，在既有授权内继续推进。具体判定、失败分支与跨项目迁移见[阶段设计手册](references/milestone-design-and-validation.md)。

## 个人实验参考如何使用

当前首要案例是[本项目最终选定实验](references/selected-experiments-thermal-tire-ggv.md)：整体有效性 → 告警经验与记忆作用 → 新赛道迁移 → 实车在线开环评估。优先借鉴其“系统效果—机制解释—新条件—真实场景”的论证结构，以及整体有效性内部的过程、空间差异、性能、复用、成本和消融证据。

设计或组织新项目实验时，将这些职责映射到当前贡献，写清采用、合并或不适用的部分即可；不要求固定四组实验。案例中的具体平台、统计单位、数值与图表数量仍是案例参数。之后新增项目进入个人索引，各案例按适用问题检索，不自动用最新案例覆盖所有旧偏好。

项目事实和临时纠正日常写入项目记忆；用户要求“更新这个 skill”“把本项目经验沉淀进去”时，直接按更新流程完成。若尚无跨项目更新任务，把经验候选留在项目记录，不在普通局部任务中顺带改全局 skill。

## 从 0 到 1 的验收链

下表是粗粒度能力链。用上述 milestone 方法将当前缺口拆成可验收阶段，根据项目裁剪，不强制编号、文件名、实验数或固定顺序。

| 阶段 | 要回答的问题 | 进入下一阶段的证据 |
|---|---|---|
| 目标与定位 | 做给谁，解决什么，完成意味着什么？ | 可观察目标、范围、资源及首个验证动作 |
| 最小系统 | 输入能否经核心链路产生有效输出？ | 实际运行、有效数据、复现命令和故障定位入口 |
| 核心机制 | 新机制是否真的参与并改变结果？ | 输入→决策→执行→反馈的可追踪链及必要对照 |
| 完整系统 | 局部机制能否在目标流程中持续工作？ | 集成运行、状态一致性、重启/复用证据（适用时） |
| 正式评价 | 相比合理替代方案，价值与代价是什么？ | 预先约定口径、共同预算/条件、完整尝试和对照 |
| 外部适用性 | 在新条件或真实环境中成立到哪一步？ | 明确变化与保持项，区分案例、独立重复和总体结论 |
| 表达与交付 | 他人能否理解、检查和复现？ | 主张对应证据，图文一致，最终文件和源包实际验证 |

每阶段完成仅代表该阶段验收通过。预测精度改善不自动证明闭环收益；最终性能不自动覆盖学习成本；开环建议不自动证明控制效果；一项迁移案例不自动证明广泛泛化。

## 不让上下文在多轮中漂移

维护一个当前入口，链接历史细节而不复制全部日志：

- 目标和一句话主线；当前权威版本及本轮授权范围。
- 持续生效的用户要求，以及仅适用于某一轮的临时约束。
- 当前实现、实验状态、事实来源和主张—证据对应。
- 关键决策：原因、被替代判断、影响范围和生效版本。
- 复现入口、最终产物、已验证内容、未解决问题与下一步。

新纠正使旧判断失效时，更新当前入口并保留可追溯历史。文件修改时间不能单独决定权威性；先核对对象、版本、来源和用户明确选择。存在真实冲突时，标明冲突并针对该事实澄清，不靠润色悄悄选边。

## 专项工具与边界

本 skill 负责编排，不要求安装一整套依赖。环境有合适的文献、统计、作图、写作、LaTeX、PDF 或增删稿技能时，按当前交付调用并先读其说明。缺少专项技能时执行等价检查，不虚构已调用或已通过。

多智能体可并行做独立资料检查、模块实现和交叉审阅。共享目标、术语、证据口径与写入范围；由主执行者整合并验证。避免同时修改同一文件或争用同一实验设备。

未来物理实验、收费长任务、外部发布、发送消息或破坏性操作不因加载本 skill 获得新授权；所需操作未授权时，先完成可逆准备和检查。运行受阻时保留现场并说明具体缺口，不冒充执行成功。

## 交付前的闭合检查

按当前任务选择必要项，不把所有任务变成全面审计：

1. 请求的实际结果已完成，而非只有计划、脚本或草稿入口。
2. 验证针对真实行为或最终产物；分清本次实测、历史记录和未执行项。
3. 数字、单位、术语、图表和结论与同一版本的证据对应。
4. 最终目录/压缩包已更新；需要独立使用的包已在独立目录检查。
5. 当前入口已记录变化、未完成项和下一步，不覆盖原始证据。

用户可只说：`使用 $ai-research-project 接着推进这个项目。` 从现有记忆恢复具体工作，只有缺失且真正影响执行的信息才需要用户补充。
