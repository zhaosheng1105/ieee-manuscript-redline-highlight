# IEEE manuscript revision with visual redlines

把作者已有稿件改得更清楚、更准确，并让每次改动可检查、可回退。修改强度由用户的要求与实际问题决定；已有清晰论证和自然表达应当保留。吸收反防御性写作的叙事原则：围绕最有证据支撑的学术价值组织表达，而非平均汇报所有工作；叙事取舍始终服从科学事实、证据完整性和授权范围。

## 确定版本与范围

- 优先采用用户指定的权威版本。用户同时提供同一版本的 Overleaf ZIP 和 PDF 时，以 ZIP 为可编辑源码、PDF 为排版与阅读参照；不要混用工作区中的旧同名章节。
- 记录本轮章节范围、修订目标和比较基线。区分“相对原始稿的累计改动”和“相对上一轮的本轮改动”，在交付物或报告中标明。沿用已约定的基线；未约定时，从本轮起始版本比较并说明。
- 修改前保存当前源码和交付物的 checkpoint。用独立修订目录保护原始下载文件，保留原始 ZIP 的成员清单，便于干净打包。
- 仅修改授权章节。若衔接需要动到其他章节，先判断用户是否已授权；没有授权时在报告中提出具体关联修改。用户要求“每章完成后停止”才逐章停下；否则完成所请求的范围。

## 先理解，再修订

先通读目标章节及其必要上下文，识别具体的问题：概念定义顺序、论证跳步、事实不准确、结论强于证据、重复解释、难读的句子。不要为了产生修改量重写全文，也不要按禁词表机械替换普通学术词汇。

实验章节重点检查“试验设置—观察结果—可支持的解释”是否连贯。保留作者已有分析、重要对比、失败情形和不利结果；不能以“去防御性”或“增强说服力”为由替换评价指标、抹去负面证据或删除决定结论适用范围的限定。

需要核实技术表述时，读取与该表述直接相关的代码、配置、日志、图表来源或作者确认，按以下边界处理：

- 区分模型预测与实测、离线回放与在线部署、建议值与实际施加值、观测记忆与闭环控制、训练拟合与独立测试。不要把这些概念在润色中合并。
- 保存数字、单位、样本量、阈值不等号、统计口径和因果方向。确需纠正时，说明依据及对结论的影响；不要凭文风偏好改动它们。
- 将关键事实标记为“原文陈述”“作者确认”“本地材料核实”或“待核实”，必要时写进修订报告，避免把证据等级悄悄升级。
- 本地没有找到日志，并不能否定作者确认的实验存在。作者确认可支持对应事实，但不能自动验证具体数值、表格来源或部署细节。不要把未核实的对应关系写成已核实。
- 疑点会实质改变论述时，提出一个具体问题，同时继续不依赖答案的工作。不要在缺少证据时自行把在线实验改写成离线实验，或反向改写。

## 按学术叙事修改

### 让最强证据承担主线

先用一句工作笔记明确“本文在什么条件下，为谁解决了什么问题，证据支持的独特价值是什么”，再判断目标章节是否服务于这一主张。价值可以是新能力、新机制、更低成本、更强适用性，或明确约束下有意义的权衡；不预设一定存在全面领先的性能优势。该笔记用于修订判断，不必强行加入正文。

- **用问题和证据组织，而非按工作时间汇报。** 按“问题为何重要—已有方法缺口—本文解法—证据与解释”建立逻辑。删去无助于理解的尝试过程和重复描述；涉及复现、关键设计依据或有效性判断的过程信息应保留。
- **让结果的价值可读。** 不只复述表格数字，要说明哪个结果支持哪项主张、优势出现在什么条件下，以及对目标应用有何意义。机理尚未被验证时，将解释标为解释或假设，不能写成已证实因果。
- **不让局部结果承担整体冠军的主张。** 某指标不占优时，准确报告该结果，并检查核心贡献是否本来就在其他有证据支持的目标或约束上。缩小过宽主张，保留读者评估权衡所需的对比；不得为了突出优势而事后替换指标、筛选有利样本或改变比较口径。
- **叙事重构受范围约束。** 原有主线不受证据支持时，在授权章节内围绕已成立的价值调整结构。需要更换全篇定位、标题、摘要或实验设计时，提出具体建议；未授权时不擅自扩大修改范围，也不虚构新贡献。

### 去掉自我削弱，保留准确边界

用自然、直接的 IEEE 学术英语交代研究对象、方法、结果与解释。删去空泛引导句、重复定义和项目汇报式过程描述；保留有信息量的技术细节。定义放在首次需要它的位置，后文通过符号或交叉引用衔接。

- 不替审稿人制造无证据支持的负面总评。不把局部下降扩大成“方法整体失效”，不以“遗憾的是”“存在严重不足”等情绪化判断代替具体观察。
- 不机械禁用 only、limited、however、outperform 等词。若其准确表达比较结果、实验条件或适用边界，应保留；改的是无依据的自我贬低和反复辩解，不是普通学术表达。
- 不以“不说输”为由隐去失败或性能下降。需要讨论时，写清场景、指标、幅度和对结论的实际影响；目标差异或合理权衡只能在证据支持时用作解释，不能成为通用借口。
- 证据不足时，优先把断言改成准确、具体的结论，不给整段堆叠免责声明。保留决定结论成立的限定，不在同一段反复申辩同一边界。

调整结构应服务于读者理解，不能改变方法或实验的实际含义。已经准确、通顺的作者表达不必改写。

### 按章节职责安排信息

仅在对应章节属于授权范围时应用：

- **摘要与引言：** 尽早建立重要问题、关键缺口、独特解法和最有分量的结果，避免以实现流水账或大量背景淹没贡献。不强制固定句数或模板；必要条件随相关主张交代，不在贡献尚未清楚时堆叠无关不足。
- **方法：** 围绕解决问题所必需的机制解释设计，保留读者理解、实现和复现实验所需的信息，避免把软件模块清单当作方法贡献。
- **实验：** 让每项实验承担明确职责，如验证核心效果、关键机制、目标场景价值或排除替代解释。按论证职责组织结果，不按运行顺序堆叠日志。重复且不影响判断的说明可合并；移动或删减实验材料前，确认不会隐去反例、削弱基线公平性或改变结论边界，并保留材料去向供核查。
- **结论：** 强化“解决了什么、提出了什么、证明了什么及其意义”，不突然引入新的负面判断或未经论证的新贡献。必要的局限性仍应准确保留，并遵守用户或期刊要求。

### 交稿前检查叙事与证据是否一致

- 核心价值是否能从正文和结果中直接辨认，而非依赖读者自行猜测？
- 是否有无证据支持的责任扩张、无关自我审查，或把局部现象泛化成整体缺陷的句子？
- 删除、压缩或移动的内容是否包含重要反例、评价口径、复现细节或结论成立条件？
- 是否把不占优的结果包装成优势，或把尚未验证的解释升级成事实？
- 修改是否仍在授权范围内，并保留了准确、自然的作者表达？

## 生成与核验交付物

LaTeX/Overleaf 的编译、标记样式及常见陷阱见 [references/latex-redline.md](references/latex-redline.md)，生成 PDF 增删对照时读取该文件。

- 提供净稿和可视化对照：新增文字黄色高亮，删除文字红色删除线，或采用用户指定样式。不要用只展示新稿的彩色 PDF 冒充完整增删对照。
- 编译并实际渲染、查看改动页；检查公式、引用、图表、换行、遮挡和标记完整性。发现预先存在的警告时区分新旧，不要仅因旧警告改动范围外内容。
- 对照基线检查修改范围，以及公式、数值、单位、标签、引用、图表文件是否发生非预期变化。对照中的旧文与新文应能与各自源码对应；长段移动或重写尤其要检查没有丢文。
- 将通过验证的产物复制到约定交付位置，重新打包并核对内容，再报告完成；不能把临时构建成功当成最终文件已经更新。
- 用户需要修订报告时，记录具体原因、证据状态和真实 before/after 摘录。摘录必须来自对应版本；例子数量由有效改动决定，除非用户明确指定数量。

最终回复按用户偏好简洁交付文件路径。若用户只要文件名和位置，不额外展开论文点评。存在实质未完成项时说明具体缺口，不声称全部完成。
