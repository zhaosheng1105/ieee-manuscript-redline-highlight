# 常用接口操作配方

这里把短请求转换为少量原生命令及效果核验。只执行本次需要的操作；不自动启动算法栈、采集器或实验队列。
本页语法来自本机历史使用与 CLI 实现核对；在其他安装上先用对应 `--help` 核对版本差异。

## 1. 命令约定与请求范围

示例假定 `avrs` 已在 PATH，目标对象叫 `ego`。实际使用时替换为已经发现或用户指定的对象。
CLI 连接设置采用该安装自身配置；不要因示例出现 `ego` 就把其他实例的目标对象改名。
如果可执行文件不在 PATH，用已发现的绝对路径替换 `avrs`；本机路径见运行环境参考。

- 用户说“把四轮改成 0.9”：执行设置并读回，完成后保留 0.9。
- 用户说“临时改成 0.9，检查后恢复”：先保存实际基线，执行检查，再恢复并读回。
- 用户说“只告诉我命令”：返回命令，不连接或控制模拟器。
- 用户说“继续之前的测试”：先读取当前状态及本项目记录，再接续已明确的范围。
- 已明确请求的运行时改值无须反复确认；本 skill 和历史采集授权本身不授权未来其他操作。
- 仅在缺少必要目标、数值或单位且无法由现有上下文确定时提问。

## 2. 读取四轮物理摩擦倍率

```bash
avrs vd get-friction-modifier All --object-name ego
```

读取并报告 FL、FR、RL、RR 四个值。返回可能是普通文本，也可能是包含转义换行的 JSON 文本封装。
解析时提取实际响应字符串，检查四轮齐全、数值有限；不要用缺省 1.0 填补缺失轮胎。
官方 CLI 将 0 解释为无抓地，不应把原项目适配器的正值限制当作原生接口限制；负值或其他异常值须查当前接口定义。
这一步读取的是模拟器物理摩擦倍率，不是规划器的能力倍率或实际抓地利用率。
若请求只是查询，读到并解释结果即可，不自动修改任何参数。

## 3. 设置全部轮胎并验证

用户已经明确要求将全部轮胎改为 0.9 时：

```bash
avrs vd get-friction-modifier All --object-name ego
avrs vd set-friction-modifier 0.9 All --object-name ego
avrs vd get-friction-modifier All --object-name ego
```

命令按上述顺序独立执行并检查结果，不把三条并行提交。
保留第一次查询的原值，便于用户后来要求恢复；本次没有恢复要求时，完成后保留目标值。
检查最终 FL、FR、RL、RR 均为 0.9。浮点显示有舍入时采用合理数值容差，而非字符串相等。
项目历史适配器使用 `rel_tol=1e-5, abs_tol=2e-6`；这些是读回比较容差，不是官方物理精度承诺。
设置回执成功只能说明请求被接受；最终 get 才能支持“已经设置并验证”的结论。

## 4. 设置单轮或不同轮胎值

参数顺序是 `数值 轮胎`，轮胎名使用 `FL`、`FR`、`RL`、`RR`。

```bash
avrs vd get-friction-modifier All --object-name ego
avrs vd set-friction-modifier 0.85 RR --object-name ego
avrs vd get-friction-modifier All --object-name ego
```

核验 RR 变成 0.85，其他三轮仍与刚才的基线一致。
用户要求四轮不同值时，依次设置目标轮胎，然后查询全部四轮。
四次逐轮写入不是一个原子操作；某次失败后，前面成功的轮胎可能已改变。
出现部分成功时，先读回实际状态并报告，不把该轮操作标成完整成功，也不盲目重放整组命令。
用户只要求单轮调整时，不顺手重写其他轮胎。

## 5. 临时改值与恢复实际基线

适用于用户明确要求“试一下后恢复”“临时调整”或已约定退出恢复的短任务。

1. get 全部四轮，保存各轮原值和目标对象；确认读到完整基线后再写。
2. 设置临时值，get 核验。
3. 完成本次指定检查。
4. 恢复启动前读到的四轮原值，再 get 核验恢复结果。

若原来四轮相同，可一次恢复 `All`；若不同，应逐轮恢复。
以下仅演示一组已读取的不同基线，不能不经查询直接采用：

```bash
avrs vd set-friction-modifier 1.0 FL --object-name ego
avrs vd set-friction-modifier 0.98 FR --object-name ego
avrs vd set-friction-modifier 1.02 RL --object-name ego
avrs vd set-friction-modifier 1.01 RR --object-name ego
avrs vd get-friction-modifier All --object-name ego
```

恢复前若发现其他控制者或用户已再次改值，先确定本次仍应恢复的目标，不覆盖后来的有效更改。
“恢复默认”与“恢复刚才的值”不同：默认值须有配置依据，不能推测为 1.0。
若基线没有保存，明确说明不能可靠恢复原值；当前 get 只能告诉当前值。
长期设置请求不自动回滚。结束聊天、关闭查询进程也不代表要撤销用户要求保留的设置。

## 6. 复位到赛道

```bash
avrs reset-to-track --object-name ego
```

适合用户明确要求“把车复位回赛道”。这不是重新加载整个环境，也不等于恢复完整隐藏动力学状态。
有驾驶控制器运行时，先辨认它是否会继续发送旧指令；使用该控制器已知的停车/暂停方法协调复位。
只管理本次明确拥有或用户授权管理的进程，不为复位杀掉所有 ROS 节点或容器。
执行后读取该对象位姿，确认位置、航向及后续状态更新符合要求。
有项目轨迹时，再检查实际落点是否回到可跟踪范围；没有轨迹时不编造距离验收结果。
若原算法因定位或轨迹有效性错误停止，需要按其运行流程重启，而不是扩大门限掩盖错误。
复位后的差分速度可能受位置跳变影响；等待新鲜连续位姿，不把瞬移差分当实际高速。

## 7. 移动到指定地标

```bash
avrs move-to-landmark MvStart0 --object-name ego
```

`MvStart0` 是本项目使用过的地标示例；其他环境应先读取实际地标列表或当前环境配置。
检查返回是否成功，再查询位姿。成功字符串不能替代落点与航向核验。
地标出生点不一定与项目的优化赛车线完全重合；不要自动认定是维修区或规划起点。
用户只要求去地标时，核验后结束，不自动追加 teleport 到本项目参考轨迹。

## 8. 按 NED 坐标瞬移

使用真实已确定的坐标替换下例符号；符号不是可直接执行的数值：

```text
avrs teleport X_NORTH_M Y_EAST_M Z_DOWN_M --frame ned --yaw YAW_DEG --object-name ego
```

位置顺序为 x、y、z；NED 对应北、东、下，单位米；`--yaw` 使用度。
不要把地图资源中的厘米值直接传给 NED 米制接口，也不要把弧度直接放进 `--yaw`。
`--frame ned` 要显式保留，避免依赖其他安装的默认坐标系。
只知道平面位置时，不猜地面高度；从当前位姿、有效地标或已核对地图取得 z。
规划轨迹若是 ENU 或另一个地理原点，先完成坐标和航向转换，再发请求。
不同真值消息对四元数/yaw 的约定可能不同；验收应按当前版本真实消息语义转换。
执行前记录目标坐标、坐标系、单位和原位姿；执行后读取新位姿并比较位置与方向。
位置成功但方向错误也视为未达成请求，不让算法直接带着错误姿态继续运行。

本项目 Yas North 曾使用如下**案例专用**平面逆映射：

```text
ned_x = plan_y - 123.821393749
ned_y = plan_x - 32.738037303
yaw_deg = 90 - degrees(plan_course)
ned_z = 已取得的有效 NED 高度
```

这些原点偏置和航向表达不能复制到其他赛道或版本；它们是本项目轨迹与模拟器约定的结果。
复用时先核对新环境和规划原点，不能通过放大跟踪误差门限补偿错误转换。

## 9. 冲突、失败与停止条件

- 同一参数保持一个有效写入者。持续温度适配器可能在下一周期覆盖手动摩擦设置。
- 用户只要求一次改值时，先识别明显冲突；不要另起持续写入循环与原适配器竞争。
- 命令超时或连接中断意味着结果可能未知，不能断言“未生效”。先做只读状态检查。
- 只读检查恢复后，按实际状态决定是否还需一次有界重试；不要无限循环或快速连发写请求。
- 如果无法读回、目标对象消失、响应对应错误对象或值持续被覆盖，停止后续写入并报告具体状态。
- reset/teleport 超时后先读位姿，避免重复位移或重复重置；加载等非幂等动作尤须避免盲重试。
- 部分轮胎写入成功时记录四轮现状；只有本次约定临时操作时才按已保存基线尝试恢复。
- 用当前接口错误解释失败；不因为网络或 sandbox 拒绝而换工具绕过执行限制。

## 10. 短请求到动作的映射

| 用户说法 | 最小动作 | 完成证据 |
|---|---|---|
| 看看当前摩擦倍率 | get All | 四轮实际返回值 |
| 四轮设为 0.9 | 读基线 → set All → get | 四轮均为目标，保留设置 |
| 右后轮设为 0.85 | 读基线 → set RR → get | RR 达标，其余轮未被本次改动 |
| 临时降一点测试后恢复 | 确定目标 → 保存基线 → 修改与检查 → 恢复 | 临时值及恢复值均读回 |
| 把车拉回赛道 | 协调已有控制器 → reset-to-track → 查位姿 | 新鲜位姿与赛道位置 |
| 回到 MvStart0 | 核实地标存在 → move-to-landmark → 查位姿 | 实际地标落点 |
| 瞬移到指定 NED 坐标 | 确定米/度与高度 → teleport → 查位姿 | 位置和航向比较 |
| 调高规划抓地倍率 | 识别为算法桥接参数 | 见运行环境参考，不误写物理摩擦 |
